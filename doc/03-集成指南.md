# 集成指南（面向「海宁方言辞典」协作编纂系统）

目标仓库：[zjhncbx/haining-dialect-dictionary](https://github.com/zjhncbx/haining-dialect-dictionary)
（GPL-3.0；本仓库 Apache-2.0 与之兼容，作为**字典数据依赖**引入，不合并代码）。

本仓库解决两件事：

1. **自动繁简转换** —— 编辑者用简体录入，系统按《大陆标准繁体汉字海宁吴语修订方案》
   输出规范繁体；检索 / 对外展示时再转回简体；导入港台、旧字形、异体混杂的旧资料时
   一键规范化。
2. **直接输入修订后的繁体正字** —— 通过 Rime 词库，让 `併 / 並 / 喫 / 衹 / 隻 /
   鬨 / 疘 / 閤 / 箇 / 𬮤` 等分立正字可直接由拼音打出（见 [04-Rime部署](04-Rime部署.md)）。

## 一、三种接入方式

| 场景 | 方案 | 依赖 |
| --- | --- | --- |
| 服务端 Python（推荐，语义最完整） | 直接加载 `opencc/*.json` | `pip install opencc`（≥1.3.2） |
| Node / 浏览器（无原生库） | `tools/export_web_dict.py` → JSON → 最长匹配 | 无 |
| OpenCC CLI / 其它语言绑定 | 把 `opencc/` 拷到 OpenCC 数据目录，用方案名调用 | OpenCC ≥1.3.2 |

### 1.1 服务端 Python

```python
import opencc, os
CFG = '/path/to/OpenCC-HainingWu/opencc'
s2hn  = opencc.OpenCC(os.path.join(CFG, 's2hn.json'))   # 简 -> 修订繁
hn2s  = opencc.OpenCC(os.path.join(CFG, 'hn2s.json'))   # 修订繁 -> 简
t2hn  = opencc.OpenCC(os.path.join(CFG, 't2hn.json'))   # 任意繁 -> 修订繁

s2hn.convert('合并 并非 吃饭 个中 真个')
# => '合併 並非 喫飯 箇中 真个'
```

OpenCC 支持直接传 json 绝对路径，字典按 json 所在目录解析，
**不需要把文件安装到系统目录**，容器内挂载仓库即可。

完整封装（含词条字段转换、一致性校验）见
[`examples/python/convert.py`](../examples/python/convert.py)。

### 1.2 Node / 浏览器

```bash
python tools/export_web_dict.py       # 生成 dist/hn-dicts.json（约 2.6 MB）
node examples/js/convert.mjs
```

```js
import { loadDictionaries, createConverter } from './examples/js/convert.mjs';
const d = await loadDictionaries('../../dist/hn-dicts.json');
const { toTraditional, toSimplified, normalize } = createConverter(d);
```

转换器按 **Unicode 码点** 做最长匹配，能正确处理 `𬮤` 等扩展区汉字；
浏览器端把 `dist/hn-dicts.json` 作为静态资源加载即可，无需 WASM。

> Web 版取每个 key 的**首选值**，不提供 OpenCC 的候选字（jieba）功能。
> 需要候选字请用服务端方案。

### 1.3 OpenCC CLI

```bash
cp -r opencc/* "$(python -c "import opencc,os;print(os.path.join(os.path.dirname(opencc.__file__),'clib','share','opencc'))")"
opencc -c s2hn.json -i input.txt -o output.txt
```

## 二、辞典数据模型建议

「词目—义项—例句」三层结构（见辞典仓库 README 第四节）建议同时存两栏：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `headword_hn` | string | **规范字段**，修订版繁体（编辑、展示、导出繁体的唯一真源） |
| `headword_s` | string | 派生字段，由 `hn2s` 生成，供检索 / 简版展示 / 拼音排序兜底 |
| `senses[].text_hn` / `examples[].text_hn` | string | 同上，正文一律存修订繁体 |
| `revised_at`, `dict_version` | string | 记录所用本仓库 commit / tag，便于日后追溯与批量重转 |

约定：

- **只把 `*_hn` 当真源**，简体字段一律由转换器派生、不手工编辑，避免双写漂移。
- 录入时编辑者用简体（或 Rime 直接打修订繁体），提交前跑一次 `s2hn` 规范化；
  若提交内容本身已是繁体（含港台字形），先跑 `t2hn`。
- 导入 2016 年以来的 Excel 旧资料时：`t2hn → 人工校对 → 入库`。

## 三、CI 校验（建议加入辞典仓库的流水线）

```yaml
- name: 校验繁简字段一致性
  run: |
    pip install opencc
    python /path/to/OpenCC-HainingWu/tools/verify.py
    python your_project/check_entries.py   # 对每条词条断言：
                                           #   s2hn(headword_s) == headword_hn
                                           #   t2hn(headword_hn) == headword_hn
```

第二条断言很关键：**规范繁体字段必须是 `t2hn` 的不动点**。若不成立，
说明词条里混入了未修订的异体字或港台字形，应退回编辑者校对，而不是静默改写。

## 四、版本与协作

- 本仓库修订规则集中在 `rules/overrides.tsv` 与 `tools/rules.py`，
  发现漏转 / 误转时补词条，然后：

  ```bash
  python tools/build.py --upstream /path/to/upstream/t2gov   # 重建
  python tools/verify.py                                      # 18 项回归
  python tools/export_web_dict.py                              # 重新导出前端字典
  ```

- 辞典系统应以**固定 commit / tag**依赖本仓库，不要直接跟 `main`。
  字典变更会影响历史词条，升级时先全量 `t2hn` 不动点扫描，再批量重转。

## 五、常见问答

**Q：为什么「合并」是「合併」，不是上游的「合并」？**
修订方案把「并 / 併 / 並」分立为三个繁体正字，按古音义项分派：
并（府盈切，并州）、併（卑政切，合并）、並（蒲迥切，並非）。

**Q：「真个」为什么不是「真個」？**
「个 / 個 / 箇」三分：个（助词）、個（量词、名词）、箇（指示代词）。

**Q：「内𬮤」的「𬮤」打不出来怎么办？**
用本仓库 Rime 词库（`ge` 可打出 `𬮤` 与 `閤`）；或先写「内閤」再由
`t2hn` 保留、`hn2s` 转成「内𬮤」。Web 端请用支持 CJK 扩展区的最新字体。
